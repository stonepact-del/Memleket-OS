## Testing doctrine for debt work

For tricky debt or bugs: identify concrete failure modes; write a behavioural regression test; prove it fails for the intended reason; implement the smallest change; prove the regression passes; run the related suite; then run full repository verification. Cover invalid and interrupted paths, and make assertions narrow enough that the known failure cannot slip through. Never write a test that only restates the newly extracted implementation.
